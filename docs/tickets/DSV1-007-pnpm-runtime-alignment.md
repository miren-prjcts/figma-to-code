# DSV1-007 — pnpm Runtime and Build-Script Alignment

## Objective

Restore reliable local verification by aligning the managed environment with the repository's declared pnpm version and removing configuration generated by a mismatched runtime.

## Findings

- `package.json` and CI pin pnpm `9.15.4`; the managed environment invoked pnpm `11.19.0`.
- pnpm 11 generated `allowBuilds` placeholders in `pnpm-workspace.yaml`; those values are invalid until explicitly set to `true` or `false`.
- The repository does not use `next/image` or import `sharp` directly.

## Scope

1. Preserve pnpm `9.15.4` as the project runtime and add an explicit `engines.pnpm` constraint.
2. Remove the pnpm-11-only placeholder `allowBuilds` map without silently approving build scripts.
3. Update setup documentation so local development and CI use the same Corepack-managed pnpm version.
4. Restore dependencies only with pnpm 9.15.4 and a frozen lockfile, then run the complete verification suite.

## Security boundary

Do not approve `esbuild` or `sharp` build scripts under pnpm 11 and do not upgrade to pnpm 11 in this ticket. Both require separate, reviewed security/migration decisions. Do not claim install or verification success if registry access remains unavailable.

## Acceptance criteria

- No placeholder build-script approvals remain.
- pnpm 9.15.4 is enforced consistently locally and in CI.
- A frozen install and full verification suite run with pnpm 9.15.4, or each unavailable environment dependency is recorded precisely.
- Documentation distinguishes repository configuration from managed-environment network restrictions.
